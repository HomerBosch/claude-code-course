Update this file once code exists, with the build, lint and test commands (including how to run a single test) and a short note on the architecture.

## How to explain changes

The repository owner is new to Git and coding. After every change, explain it in plain language:

- Say what changed and why, in everyday words. Avoid jargon, or explain a technical term the first time you use it.
- Explain any Git step you took (for example, what a commit or a push is and what it did here).
- Say whether you checked that the change works, and how.
- Point out anything the owner needs to decide or do next.
